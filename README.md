### 第8章 封闭式自动化检验实战

*预设标准答案，通过 Test Case（测试用例）严格检验 AI 生成代码或 Prompt 的逻辑严密性与格式稳定性。*

#### 实战一：日常场景的复杂逻辑与结构化提取（水果店计费系统）

* **场景：** 编写一段高阶提示词（Prompt），让 AI 处理自然语言输入（如：“草莓3斤，需要果切，节日期间，需要环保袋”），并根据以下严格规则计算费用：
1. **阶梯与条件折扣：** 苹果8元/斤、草莓22元/斤、葡萄15元/斤。满3斤同种水果打9折并向下取整。
2. **附加服务费：** 果切费2元/斤（按总斤数计）。
3. **特殊溢价：** 节日期间，水果费与果切费合计后加收20%，并向上取整。
4. **固定耗材：** 环保袋2元。


输入：一段自然语言输入

输出：JSON输出，仅两个字段———仅输出包含 `total_bill`（最终总价）和 `fruit_cost`（节假日加价前的折后水果费）两个字段的标准 JSON 字符串，过滤任何多余的解释性废话（幻觉控制）。

* **检验与难点：** * **运算次序与精度控制：** 检验 AI 能否严格遵循“折扣向下取整 $\rightarrow$ 叠加服务费 $\rightarrow$ 溢价向上取整 $\rightarrow$ 叠加耗材”的先后顺序计算。

* **自动化测试：** 编写 Python 检验脚本，批量输入不同的顾客购买描述，解析返回的 JSON 并与人工预设的正确金额进行断言比对（Assert）。

### 实战二：动态寻优与分段逻辑提取（网约车计费系统）

* **场景：** 编写一段高阶提示词（Prompt），让 AI 处理包含时间、里程、优惠和附加费用的自然语言输入（如：“昨晚11点半打车回家，一共跑了14公里，交了10块钱过路费，账户里有一张满40减8元的券和一张75折券”），并根据以下严格规则计算最优费用：

1. **分段里程计费：** * 起步价 13元（包含前 3公里）。
* 超出起步里程部分：3 到 10公里（含）按 2.5元/公里计费；超过 10公里的远途部分按 3.5元/公里计费（远途加价）。


2. **时段浮动费率：** * 若出发时间处于夜间（23:00 - 06:00），计算出的**纯里程费**（不含起步价）需要加收 20% 的夜间服务费，且该部分计算结果**向上取整**。
3. **动态折扣（互斥原则）：** * 将起步价与最终里程费相加得到“基础车费”。
* 若用户同时拥有“满减券”和“折扣券”，系统需自动比较两种优惠方案，**强制选用对用户最划算（最终车费最低）的方案**。折扣后的车费**向下取整**。


4. **固定附加费：** * 高速费、停车费等附加费用**不参与任何折扣**，在最终扣款时直接原价叠加。

* **输入：** 一段包含打车里程、时间、路桥费及可用优惠券的自然语言描述。
* **输出：** 标准 JSON 字符串，仅包含以下三个字段，绝对过滤任何解释性废话：
* `total_fare`（最终需支付的总金额）
* `base_fare`（打折前的基础车费总额，不含附加费）
* `applied_discount`（实际生效的优惠策略，输出字符串如 "满40减8" 或 "75折"）


* **检验与难点：** * **逻辑分叉与寻优能力：** 检验 AI 是否具备“分支计算并比较”的能力（AI 必须在隐式思维过程中同时计算满减和打折的结果，比较大小后才能得出 `applied_discount`）。
* **作用域陷阱：** 检验 AI 是否能精准区分各类费用的作用域（夜间加价**仅**针对超出的里程费；打折**仅**针对基础车费，绝对不能把过路费也打折）。
* **自动化测试挑战：** 编写 Python 测试脚本，构造极具迷惑性的 Edge Case。例如：某一里程下，满减和打折的最终金额完全一致，测试 AI 的边界处理机制；或者总里程为 2.5公里（未超起步价），测试 AI 是否会错误计算负数里程。



#### 实战三：算法性能与边界控制（组合数学与模运算求解器）

* **场景：** 编写一段高阶提示词（Prompt），要求 AI 编写一个结合模运算的高效 Python 求解算法，解决特定的组合数学问题：

1. **核心逻辑（整数划分与排列）：** 计算将 $n$ 个相同物品划分为 $k$ 个非空组的方案数，随后将结果乘以 $m$ 个不同物品的全排列数。
2. **模运算约束：** 由于组合数结果极大，要求在动态规划的每一次状态转移（加法）以及最终的乘法步骤中，严格对 $10^9 + 7$ 取模。
3. **性能要求：** 针对大数据范围（ $n \le 1000$ , $m \le 10^5$），强制要求 AI 使用空间复杂度优化的动态规划（如一维滚动数组），避免内存溢出或计算超时。

* **输入：** 三个正整数参数  $n$ 、 $k$ 、 $m$ 。
* **输出：** 纯代码输出——仅输出一个名为 `solve(n, k, m)` 的 Python 函数代码块。强制要求过滤任何 Markdown 标记（如 ````python`）、导入语句以外的多余代码，以及解释性废话（幻觉控制）。
* **检验与难点：** * **算法底座与同余定理：** 检验 AI 是否能写出正确的时间复杂度为 $O(n \cdot k)$ 的 DP 状态转移方程，并排查其是否在中间计算环节遗漏了取模操作（防止 Python 隐式处理超大整数导致性能急剧下降）。
* **自动化测试（OJ 判题模拟）：** 编写本地测试脚本（类似 LeetCode 的判题机），通过 `exec()` 或动态导入的方式加载 AI 生成的函数，批量传入极端边界测试用例（如 $n=1000, k=500, m=99999$）。一方面使用断言（Assert）比对计算结果的正确性，另一方面严格限制并监控函数的执行时间（如必须在 1 秒内跑完）。
